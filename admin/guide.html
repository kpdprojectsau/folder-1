KPD PROJECTS · WEBSITE GUIDE

Add a job once. The website does the rest.

Open project editor

Sign in using Login with GitHub. If prompted, sign in to the private KPD Site first, then GitHub. Only approved GitHub accounts with website repository write access can save or publish jobs. Visitors cannot change your website.

The editor connection and automatic publishing are set up. Sign in with an approved GitHub account. A new staff member needs website repository write access and access to the private KPD Site; ask the owner to arrange this. Owner connection setup/recovery is only needed when maintaining account settings, not when adding a job.

1. Add a completed job

  1. Choose Completed projects → New completed project.
  2. Enter the title, short Page URL (lower-case words separated by hyphens), suburb and summary. Add a detailed description and scope of work if helpful. Leave the completion date empty if unknown.
  3. Select the primary category and all applicable categories. Include the primary category in that list.
  4. Upload a cover photo. Add gallery photos with Add gallery photo. Write alternative text describing each picture; captions are optional. JPEG, PNG and WebP up to 12 MB are accepted. Export iPhone HEIC pictures as JPEG first.
  5. Leave Publication status as Draft, then Save. Check the preview beside the form. On smaller screens, use the preview control.
  6. When ready, set the job's Publication status → Published and save again. In the toolbar, choose Status → Ready, then Publish → Publish now. These are two separate controls: the job field controls public visibility; the toolbar status controls editorial approval.

Upload once: portrait, landscape and square photos can be mixed freely. The website keeps their proportions, limits their display height and automatically makes fast-loading sizes. You do not need to resize photos, make thumbnails or edit page layouts.

2. Edit, hide or remove a job

Open Completed projects, choose the job, change its text/photos, then preview, save and publish the update.

  • Hide a job: set Publication status to Draft and publish that change. This keeps the record but removes it from the public website.
  • Remove permanently: use Delete entry. Hiding is safer if you might need it again. GitHub history provides a recovery path.
  • Change a page URL: avoid this after publication. If necessary, enter the old path (for example /projects/old-job-name/) in Previous URLs so old links still work.

3. Add or rename a category

Open Portfolio settings → Categories. Add or edit the name, URL name, description, display order and visibility, then save and publish. Keep the URL name unchanged when only changing the display name. Lower display-order numbers appear first. Empty categories stay hidden automatically.

4. Choose homepage jobs and ordering

Turn Feature on homepage on or off inside each job. The homepage selects up to three and prioritises a spread of work categories. Use a smaller Display order number to move a job earlier in the portfolio and featured selection.

5. Preview, publish and check

The editor preview shows your job and its natural photo shapes. Save keeps work in a GitHub draft branch; it does not update the live website. Set the toolbar's Status → Ready, then Publish → Publish now merges it into the main website content. GitHub Actions then validates everything, processes the photos and releases the site. Allow a few minutes, then refresh the public project page.

A job must have both Publication status set to Published and the editorial change published. The private review Site is a separate deployment; routine editor publishing updates kpdprojects.com.au, not automatically the private review copy.

If something goes wrong

  • Sign-in expired: sign out of the editor and log in again. GitHub editor sessions expire; no changes are made by signing in.
  • Photo rejected: use JPEG, PNG or WebP, under 12 MB. Convert HEIC using your phone/photo app’s Export as JPEG option. Keep your originals.
  • Publish did not appear: check the website build. A failed check leaves the last successful website online. Fix the field or photo named in the error and publish again.

Backups

Everything is stored in your GitHub repository. Choose Code → Download ZIP there to back up the project JSON, categories and original uploads. Git history keeps previous versions. Photos and job content are not locked into a paid CMS.
